# 上市公司报告分析器（Financial Report Analysis）

> **执行前必读（防幻觉）**：本技能内容已通过 Skill 工具完整注入上下文，你**不需要**
> 用 Read/Bash 去读取任何本地路径下的 SKILL.md。你拥有 Bash/Read/Write/markitdown/
> mx-ds 等完整工具权限；tushare 数据一律经 `scripts/ts_fetch.py` 脚本调用（读环境变量
> `TUSHARE_TOKEN`，不依赖 tushare MCP）。直接按 Phase 0 开始执行。

对上市公司**年报、半年报、季报、招股说明书**做系统性分析。方法论收敛为五层质量观：
**盈利质量 / 资产质量 / 现金含量 / 成长质量 / 风险信号**，并融合杜邦分解、
唐朝排雷清单、张新民战略视角、刘姝威现金流验证。分析引擎分
四层：数据层（extraction-schema.md 的 data.json）→ 恒等式层（articulation.md 的
过程勾稽）→ 比率与基准层（frameworks.md）→ 叙事层（text-mining.md），
每层结论必须能回溯到下层证据（定义与阈值见
`references/frameworks.md` 与 `references/redflags.md`）。

**独立性声明**：本技能与股票分析类 skill（如 stock-deep-analysis）**完全独立**——互不依赖、
互不承诺接口，`reports/archive/json/*.json` 只是本技能自己的中间产物而非下游契约，需要联动时另行立项。
**不产出跨维度加权合成分**：财报分析的产出是「排除与揭示」（这份报告哪里可疑、哪里被解释），
不是「质量排序」。

## 何时使用 / 何时不用

**✅ 使用本技能：**
- 用户上传/指定一份年报、半年报、季报、招股说明书并要求分析
- 用户说「读一下这份报告」「这份财报有没有雷」「帮我分析这份招股书」

**❌ 不要使用本技能：**
- 用户只问单个指标或行情 → 直接调数据接口回答
- 用户要的是二级市场全面估值与买卖建议、多空立场构建 → 用 stock-deep-analysis。
  本技能以**已发生事项的解读**为主，方向性判断仅两种合法形态：① 多期已发生数据的结构判定
  （周期定位、账龄迁移、剪刀差趋势）；② 条件化触发线（「若 X 连续两期则 Y 成立」式可证伪的
  if-then）。**无条件未来断言与多空立场归股票分析 skill**
- 非上市公司且无任何披露文件 → 巧妇难为无米之炊

## 产出方式与文件命名

- **默认**：单文件自包含 HTML，复制 `assets/report-template.html` 骨架后填充，
  写在**当前工作目录**的 `reports/` 顶层。
  **槽位契约以 fillsheet 为唯一来源**（v0.0.18）：`calc.py --fill` 产出的填充速查表覆盖
  全部机械槽位（含 JS 数据槽可粘贴形态），填充只看 fillsheet + 模板注释；
  模板注释内嵌真实 figtitle/takeaway 示范条目供文风参照（v0.0.18 起 examples
  标杆样本退役，不再随模板改动维护副本）。
- **文件命名**：`{公司名}-{代码}-{报告类型}-{报告期}-{生成日}.html`（日期一律取报告生成日，
  格式 YYYYMMDD），如 `贵州茅台-600519-年报-2024FY-20260904.html`。
  报告类型 ∈ {年报,半年报,季报,招股书}。
- **中间产物**：markitdown 转换出的 `.md` 也存 `reports/archive/原始报告/` 下，便于复核与复用。
- 用户明确要求 Markdown 时才输出 `.md`，章节顺序与 HTML 一致。
- **完成后**：在对话中给出报告路径 + 一页摘要（三大亮点 / 三大风险）。

## 工作流程

### Phase 0：输入识别与转换

1. 报告文件获取两条路：① 用户在对话中提供文件 → 直接用；② 未提供且为 **A 股定期报告
   → 默认自动获取**（v0.0.7）：用 mx `mx_finance_search_notice` 定位公告 PDF 链接
   （tushare `anns_d` 本环境无权限 40203，不作主路径）→ curl 下载 → 转 markitdown。
   **未指定期次时取最新已披露期次**：按当前日期与披露节奏判断（一季报/年报 4/30 前、
   半年报 8/31 前、三季报 10/31 前）——如半年报已披露就不再取年报；用户明确指定期次时
   照做不打扰；搜索/下载有歧义或失败时才问用户。
   港股/美股维持 HKEX 披露易 / SEC EDGAR 路径（见 P1-9 分支）。
2. 调用 **markitdown 技能**转为 markdown，存入 `reports/archive/原始报告/`；
   **随即运行 `scripts/md_clean.py`**（v0.0.13）：把 PDF 拆碎的逻辑表行拼回、删重复
   分隔行与页眉页脚（实测 −15~21% 行数、拼行税 1.39×→1.0×），产出
   `{stem}.clean.md`（**唯一工作副本**：data.json 的 `source_md` 指向它，T8② 行号对其回核；
   原始 md 仅作溯源快照保留）与 `{stem}.index.json`（章节名→clean md 行区间 + 三表/MD&A/
   审计/附注关键块位置——**后续所有 Read 按索引精确切片，禁止无索引盲读全 md**）。
   脚本内置双不变量（数字 token 不丢 / 中文行不丢），违反即 exit 1 禁止产出。
   既有报告的 json 仍指原始 md（快照不回改，两文件共存）。
2.5 **并行派发窗（v0.0.13 起；窗口最慢项历经两轮拆分定型）**：md 转换完成后
   **一次性并行派 7 个子代理**——它们只依赖 md、不依赖 data.json，可与主线 P2~P4 全程并行：
   ①a 资产负债表+母公司提取（P1）①b 利润表+现金流量表提取（P1，含补充资料）
   ②a 资产负债附注（P1）②b 损益与经营附注（P1）
   ③ MD&A 断言与语气（P5）④ 产能/在建/股东/户数（P6）⑤ 期后事项/同业/机构预期（P7）。
   **派单 prompt 一律按 `references/subagent-prompts.md` 的模板填空**（v0.0.14）——
   禁止现场全文手写，并按公司特点加一条专属任务。
   **派发后主线立刻在窗内执行 Phase 1 批量取数**，取数完成仍有余量则做不依赖 ①② 的
   准备工作（回看检查/读模板），禁止空等回包。
   **提取类子代理（①②a②b）读 clean md + index sidecar 切片**（见 Phase 0 第 2 条）。
   **产出分块落盘（v0.0.18）**：
   各代理产出**严格按 schema 分块的 json 片段**，写入 `reports/archive/json/_chunks/{stem}/`
   （分块名见派单模板：statements_bs.json / statements_ic.json / notes_bs.json / notes_pl.json / assertions.json /
   notes_ops.json / notes_ext.json）；主线合成 = 合并 _chunks + 补 meta/derived 判断字段 +
   Phase 2.5 recon，再 `calc.py --fill` 补机械 derived——主线不再整卷手写 data.json。
   分块键名漂移由 Phase 7.5 calc 结构校验兜底（FAIL 即回炉对应分块）。
   ③④⑤ 产出同走 _chunks，Phase 8 填充时合并。**字段归属边界按 schema 块划分、互不重叠**
   （① statements/parent_statements、②a②b notes（按模板分工）、③ assertions、
   ④ notes.capacity/shareholders、⑤ notes.subsequent_events+外部）；
   回传摘要压缩成「字段=值+出处」表（供主线核对），不回传原文段落。
   单上下文降级时此窗失效、回退全串行。
3. **长文档分章策略（关键）**：年报常 200~400 页，转换后的 md 可能数十万字符。
   先读目录/章节标题定位，再按需分段读取：
   - 必定位章节：主要会计数据与财务指标、管理层讨论与分析（MD&A）、财务报告
     （三表 + 附注：收入构成/成本构成/在建工程/借款/研发）、股东情况、风险提示
   - 禁止一次性 Read 整个 md——用 Grep 定位章节锚点，Read 分页读取
4. 识别并确认：**公司名、股票代码、上市地、报告类型、报告期**。招股书无代码时用公司名。
   任一要素模糊 → 一句话向用户确认，不要猜。
   **上市地分支（P1-9）**：非 A 股（港股/美股）走 `references/data-sources.md` 三·五节
   替代路径——报告源 HKEX 披露易 / SEC EDGAR，财务主源妙想 `mx_hk_finance_data` /
   `mx_us_finance_data`；须核对**币种**（港元/人民币/美元）与**会计准则**（IFRS/US GAAP），
   A 股专属模块置灰标注「仅 A 股」，缺第二源时该标的数字加 `[单源]` 标记。

5. **回看模式（P2-18）**：先检查 `reports/` 顶层是否已有**同公司**的旧成品 HTML
   （文件名含公司名或代码）。有则读取其 `watchlist` 块（`reports/archive/json/` 同名 .json 的
   `watchlist`），按块内 `tripwire` 条件化触发线逐条核对兑现情况，
   **作为新报告的第一章「上期跟踪回顾」**（兑现 ✅/❌ + 一句话复盘）；
   上期无 JSON（旧版产物）时降级解析上期报告「下期跟踪清单」表，并在新报告注明
   「回看基于旧版 HTML 解析」——分析师的信用来自「上次说的风险兑现了吗」，
   让分析从单点快照变成连续追踪。
   **冻结纪律（T6）**：回顾章第一列必须**照抄上期 `tripwire` 原文**（禁止改写美化）；
   核对结果只**追加**写入上期 data.json 的 `watchlist[].review` 子块
   （`verdict/actual/attribution`，未兑现必填归因：假设错/时点错/口径错），
   **原 `indicator/tripwire/upper/lower` 一律不回改**——预测登记不得事后改写。

### Phase 1：数据底座（双源核对）

1. 从 md 提取三表关键科目（**最小 5 期**，P1-13）：营业收入、营业成本、归母净利润、
   扣非净利润、经营现金流净额、销售商品收到的现金、货币资金、有息负债（短期借款/
   一年内到期非流动负债/长期借款/应付债券）、应收账款、存货、合同负债、商誉、在建工程、
   研发费用、总资产、归母净资产。多期数据写入 data.json 的 `hist` 数组（旧→新）——
   趋势图、周期定位、所有「连续 2 年以上」的信号判定都依赖它。
2. 双源核对：A 股用 tushare `income` / `balancesheet` / `cashflow` / `fina_indicator`
   （一律经 `scripts/ts_fetch.py` 调用，用法见 `references/data-sources.md` 第二节开头；
   `TUSHARE_TOKEN` 未配置时 A 股降级为妙想单源核对，数字加 `[单源]` 标注）。
   **批量取数约定（v0.0.13）**：核对所需接口在**一次 shell 命令内串联多次 ts_fetch**
   （或单进程循环）一把取回再比对，禁止逐接口串行往返——串行调用是首测里可观测的
   纯等待时间；`--out` 落盘一律用工作区相对路径，**禁止 `/tmp`**——它是 Git Bash
   虚拟路径，Windows Python 不可见（比亚迪轮实测 FileNotFoundError 重试）；
   港股/美股用妙想 `mx_hk_finance_data` / `mx_us_finance_data`（tushare 港股财报接口
   本环境无权限，实测 40203）。字段速查见 `references/data-sources.md`。
3. **不一致处理**：以报告原文为准，在报告中显式标注「原文 X / 数据库 Y」。
4. **结构化中间层（强制）**：所有提取的数字写入 `reports/archive/json/{公司}-{代码}-{类型}-{期}.json`，
   结构见 `references/extraction-schema.md`。此后各 Phase 只消费/回填这份 JSON；
   Phase 8 的报告数字**只允许从 data.json 流入 HTML**——原文 → JSON（可机检）→ HTML。
   单位统一「亿元」，每个数值叶子必须带 `src` 出处，JSON 内禁止千位符字符串。
   未披露填 `null`，禁止用 0 或编造值占位。

### Phase 2：财务总览（四维 + 杜邦）

0. **商业模式识别与调焦（P1-10，先做）**：读 `references/industry-profiles.md`，把公司归入
   八类模式之一（工程建造/渠道零售/To G/软件订阅/农业养殖/资源周期/重资产制造/医药健康），
   在报告中声明「本报告重点勾稽项」与「已降级的通用信号」；该模式特有的判读
   （客户价值五维、经销商压货三条件等）按 profile 执行。
   若无法归类，声明「通用框架」并说明理由。
0.5 **周期定位（P1-13）**：用 `hist` 多期数据 + 资本开支趋势定周期阶段（上行/顶部/下行/底部，
   规则见 frameworks.md 第五节），阶段决定后续信号的解读方向——报告须声明所用阶段框架。
   **呈现层（v0.0.20/21）**：周期定位证据卡整槽退役——收入/毛利率读数本就在五年趋势图里，
   重复呈现无信息量（美的反馈）；唯一独有的 Capex 线并入趋势图卡底部迷你柱条，阶段判定
   三线判定照旧（frameworks.md 第五节），读数留底稿不进报告（卫星化学反馈定稿）。
   判词挂趋势图卡 `.wv` 大字声明行（v0.0.21 用户定案——srcline 小字对周期股
   降权过度，判词很重要须重点显示）。
1. 四维比率（公式与阈值全在 `references/frameworks.md`；**先读其「〇、口径总则」**——
   存量/流量年化、平均余额期初、同口径同比四条规矩，**数值因子不在本文件复述**，防双写漂移）。
   **机械字段一律 `calc.py <json> --fill` 预填**（v0.0.13）：ratios 全 14 项+hist、dupont
   连环替代、risk_models、stress、cash_ts、单期八项（含 v0.0.17 的 ROIC/内生增长率）
   由脚本按唯一公式定义处写入并产出
   `{stem}.fillsheet.md` 填充速查表；**模型只补判断字段**（verdict/解释/notes/rev_factors/
   桥/recon）并照速查表抄机械槽——模型手算公式是错误源与回炉循环，**禁止**。
   **fill 会重排 JSON 格式**（单行→多行）：fill 之后再 Edit data.json 必须先重新 Read
   目标段，禁止凭 fill 前的记忆拼 old_string（比亚迪轮两次 Edit 失败的共同根因）。
   盈利能力（ROE/毛利率/净利率/ROIC + 非主营业务收入占比 X33）、营运能力（应收/存货/总资产周转 + CCC）、
   偿债能力（资产负债率/流动比率/速动比率/利息保障）、成长能力（收入/利润增速）；
   **杠杆结构**（经营杠杆 DOL / 财务杠杆 DFL，frameworks.md 第八节——方向须落到周期定位后定性，
   回答「下行期扛不扛得住」）。
2. 杜邦三分解：ROE = 净利率 × 总资产周转率 × 权益乘数，判断增长由哪一项驱动。
   **贡献归因用连环替代 + v0.0.15 因子级下钻**（规则全文在 frameworks.md 第二节，
   全部机械可复算：三口径连环替代、净利率四项分解、周转率科目贡献、杠杆有息/无息拆解、
   双驱动护栏、扣非双版、五年累计归因+因子分位）——落库 `derived.dupont`（含 closure_gap）
   / `derived.dupont_dt` / `derived.dupont5y`；figtitle 只报主驱动 + 裁决，
   不在标题复述全部分解数字；分位是位置读数非统计分位、禁用「显著」措辞。
2.5 **破产风险双模型 + 压力情景**（v0.0.12）：Altman Z + Ohlson O 并列互证（公式与纪律见
   frameworks.md 第三节——金融/地产跳过、禁止综合分、缺市值 Altman 置 null），
   流动性压力情景三档（收入 -10/20/30%，DOL/DFL 传导，第八节）；结果落 data.json
   `derived.risk_models` / `derived.stress`，报告 s7 健康检验卡各一行呈现（压力情景带
   est 徽章，「情景推演、非预测」）。现金验证时序读数（净现比/FCF 5 期均值与负值年数）
   落 `derived.cash_ts`（frameworks.md 第四节），S1 现金含量折线图（ncrline）与趋势图区引用。
3. 共同比报表：利润表各项 ÷ 收入，看结构变化。
4. **费用投入产出（P1-16）**：增量费用效率、销售费用获客效率、研发投入转化（规则见
   frameworks.md 第六节）——诊断经营效率，作为盈利质量定性依据，并入因素分析与勾稽层证据。

### Phase 2.5：勾稽验算（过程层，排雷的前置弹药）

按 `references/articulation.md` 逐条执行勾稽等式：A 组三表恒等式（现金余额/未分配利润
滚动/间接法调节/收入-收现闭环/折旧摊销/Capex/隐含利率/投资收益）+ B 组科目
Roll-forward（应收/存货/在建工程/商誉）+ C 组周期联动（CCC/DPO 双面性）
+ D 组母公司单体勾稽（货币资金/未分配利润/其他应收款/投资收益/经营现金流，
取数落 `parent_statements` 块；manual 型——判定是语境合取，calc.py 只做结构校验，
不做机械方向判定，见 extraction-schema.md 第四节）。

- 每条等式算出偏差额与偏差率，按 articulation.md 阈值做**三态判定**（✅闭合 / ⚠️可解释 /
  🔴无法解释），结果写入 `recon` 块（字段见 extraction-schema.md 第四节）；
  偏差 ≠ 造假：先查手册「常见合理解释」排除后再定级，**阈值内一律判「闭合」**
  （阈值内判可解释 = 过度立案，calc FAIL）
- **进报告的只有异常（P-5）**：⚠️/🔴 进 S2 勾稽异常清单，✅ 闭合项压为表下一行汇总；
  🔴 条目必须同步生成 signals 条目，作为 Phase 3 排雷的输入

### Phase 3：排雷扫描（双输入：信号库 + 勾稽异常清单）

两个输入源：① `references/redflags.md` 信号库逐条对照（存贷双高、利息收入与货币资金
不匹配、应收/存货异常、毛利率异常高于同行、其他应收款、商誉占比、在建工程长期挂账、
净现比异常、非经常性损益撑利润、研发资本化激进、控股股东高质押、审计非标、问询函
处罚……）；② Phase 2.5 的勾稽异常清单（recon 三态中所有 ⚠️/🔴 条目）。

- 判定升级为三维：**阈值 × 勾稽异常 × 行业模式**——单科目触阈值只是症状，
  等式偏差才指向手法（例：应收高增 + 账龄迁移加速 + 工程建造模式 = 完工百分比激进）。
  行业模式的调焦规则（各模式特有雷型、该降级的通用信号、客户价值五维、经销商压货三条件）
  见 `references/industry-profiles.md`；商业模式识别结果写入 data.json `meta.industry_profile`
- **审计视角交叉命中（P1-14）**：关键审计事项逐条映射科目 → 与该科目是否命中
  信号/勾稽异常做交叉检测，**交叉命中 = 高危直接 🔴**；同时看审计收费 3 年趋势与
  会计师更换轨迹（规则见 redflags.md 第五节）
- **人效三维（P1-15）**：收入增速 × 员工人数增速 × 支付职工现金增速的背离判定
  （redflags.md 第六节），用于识别虚增收入
- 每条信号的判定必须给出**证据 + 出处**（报告章节/附注名/原句），无证据不写；
  判定语按 redflags.md「三问范式」回答（**禁止「属正常波动」式空话**）
- 产出：**亮点清单（🟢）与风险清单（🔴/🟡）**，按严重度排序；四态判定 / 观察两行形态 /
  上限 6 条 / severity 刻度 / 汇总行句式以 redflags.md 〇节为唯一出处——**禁止加总总分**；
  全量信号清单落在 data.json `signals` 块
- 风险不是越多越好：误报会稀释可信度，每条先自问「有没有合理解释」

### Phase 4：因素分析（桥式分解）

对最新报告期的收入、成本、净利润、经营现金流变化做归因，方法模板见
`references/factor-analysis.md`：

1. **收入（三因素）**：多产品公司必拆 量效应 + 价效应 + 结构效应（mix）——结构效应
   （高/低毛利产品占比变化）常是第一驱动且性质独立；无量价数据降级为分部收入桥并如实标注。
   三效应之和必须 = Δ收入（calc.py 校验）。**分部桥分组轴（v0.0.7）**：优先与商业模式
   叙事同构的轴（industry-profiles.md 该模式声明的收入轴，如医药健康=创新药/仿制药/
   license-out），不机械照搬附注分产品表——规则全文见 factor-analysis.md 第二节；
   **多分部公司加做收入-毛利四象限**（factor-analysis.md 第六节：象限判读 + 双排名表，
   错位度 ≥2 = 资源错配信号；落 `derived.segment_quadrant` 选填块，填则 calc 复算比对）
2. **成本**：按成本构成（原材料/人工/折旧/能源）拆，解释毛利率变化
3. **净利润桥**：收入 → 毛利 → 税金及附加 → 期间费用（销售/管理/研发/财务）→ 减值
   → 投资收益 → 非经常性损益 → 所得税 → 少数股东 → 归母净利，逐项算同比贡献额，
   标明「利润变化的第一驱动」
4. **OCF 调节桥（间接法，与净利桥并列成双桥）**：净利润 → 折旧摊销/减值/递延税
   → Δ应收/Δ存货/Δ应付 → 经营现金流净额，标明「主吞噬项」；数据源为年报
   「现金流量表补充资料」，Σ 必须 = OCF（calc.py 校验）

### Phase 5：文字部分分析（重要度等同财务数据）

按 `references/text-mining.md` 框架分析 MD&A 与定性章节：

1. 管理层想表达什么：优势方向、未来发力点、对行业景气度的判断
2. **措辞对比**（若能拿到上期报告）：新增/删除/弱化的关键词，语气变化——
   语气判定必须走 text-mining.md 第二节「语气档位词表」（T7：四档词频 + 档位迁移 +
   词集合差集，可复现），**禁止无词表依据的语感表述**
3. **热门赛道重合度**：公司宣称的发力方向 vs 当下热门概念板块（tushare `dc_index`/
   `ths_index` 热榜）；区分「真布局」（有资本开支/产能/订单/研发证据）与「蹭热点」（只有文字）；
   管理层点名的重点规模数字必须补行业坐标（同行对比/行业占比/口径说明，详见 text-mining.md 第三节）
4. 风险提示章节的新增条目 = 管理层最担心的事
5. 问询函、处罚、诉讼、审计意见（mx `mx_finance_search_notice` 补充验证）

### Phase 6：产能、在建工程与股东结构

1. **在建工程/募投项目**：列明细（项目名/预算/进度/资金来源），判断主要在哪条产品线
   发力；在建工程长期不转固要追问原因；有产能数据就算产能利用率
2. **股东人数**：tushare `stk_holdernumber` 拉趋势——户数骤降 + 股价上涨 = 筹码集中；
   户数激增 = 散户接盘信号
3. **前十大股东**：`top10_holders` / `top10_floatholders` 对比上期，标出新进/退出/
   增减持的机构；配合 `stk_holdertrade` 看高管与大股东增减持方向
4. 控股股东质押率（`pledge_stat`）：>70% 进风险清单
5. **期后事项（P1-11）**：拉「报告披露日 → 分析日」的期后公告时间线
   （mx `mx_finance_search_notice`），重点核验三类：
   - **期后大额收款/回款** → 验证期末应收的真实性（跟 B1 roll-forward 联动）
   - **期后退货/合同解除** → 验证期末收入确认是否激进
   - **期后质押/减持/诉讼/债务违约** → 验证期末偿债能力与资金链
   写入 data.json `notes.subsequent_events`（date/event/verifies/src）。
   **无期后事项时必须在报告中显式写「已检查，无重大期后事项」——不悄悄缺席。**

### Phase 7：外部校验（报告之外的对照）

1. **机构预期对比**：tushare `report_rc` 拉券商盈利预测，实际收入/净利 vs 一致预期，
   算偏离度；近期研报评级与目标价变动方向（mx `mx_finance_search_news`）
2. **增收不增利判定**：收入增速 vs 归母净利增速的剪刀差；若存在，用 Phase 4 的费用桥
   解释钱去哪了（毛利率下滑 / 费用激增 / 减值）
3. **同业对比**：研发费率、毛利率、资产负债率 vs 同行业 3~5 家可比公司
   （mx `mx_stocks_screener` 或 `mx_ashare_finance_data` 批量取数）；
   **v0.0.15 起扩杜邦四列**（净利率/周转率/权益乘数/ROE，同接口批量取）——
   从比率对照升级为结构对照（回答「同业怎么赚 ROE、本公司超额来自哪个因子」）；
   **全部同业读数落 data.json `peers[]` 块**（src 必填=取数接口+日期，
   同业数字同样禁止只进 HTML 不进 JSON，T8① 回验覆盖 S7 表）
3.5 **股权激励考核线取数**（v0.0.15，四线检测落地）：mx `mx_finance_search_notice` 查
   「股权激励计划 / 考核目标 / 行权条件」取考核目标，年报「股份支付」附注取本期摊销额，
   落 `derived.threshold_check.incentive_line`（src 必填）；无激励计划时整块 null。
   保壳线（ROE 贴 6.5% 且净利率 0~3%）与再融资线（ROE 贴 10%）由 `--fill` 机械判定
4. **宏观与政策敏感性**：税率变化（所得税/优惠资质）、大宗商品（原材料占成本比高 →
   用 mx `mx_macro_data` 查对应品种价格趋势）、汇率（海外收入占比高时）
5. **债务偿付能力**：（货币资金 + 年经营现金流）÷（短期借款 + 一年内到期非流动负债）
   覆盖倍数 <1 必须进风险清单——这是康美式爆雷的核心先行信号

### Phase 7.5：计算自检（写报告的前置门禁，不通过禁止进入 Phase 8）

1. 确认 data.json 已按 `references/extraction-schema.md` 填齐本期分析涉及的全部块
2. 运行：`python "<技能目录>/scripts/calc.py" reports/archive/json/xxx.json --min-recon N`
   （N = recon 覆盖硬下限：年报 15 / 半年报 13 / 季报 8——v0.0.20 起接线为默认；
   卫星化学轮实证：不带该参数时 12/17 的覆盖率只报 WARN，漏提整份补充资料也拿了全绿）
   （技能目录 = 本技能被部署的路径；Windows 控制台已内置 UTF-8 处理）
3. **退出码 0（全绿）才允许写报告**；任何 FAIL → 回到对应 Phase 修数据后重跑，
   禁止带病写报告。WARN 需逐条确认是「口径差异」还是「漏填」
4. calc.py 校验六类：结构/出处、核心科目覆盖度、资产=负债+权益、未分配利润滚动、
   三座桥闭合（净利桥/OCF 调节桥/收入三效应）、比率复算、recon 三态一致性、信号结构；
   v0.0.12 起加四项：**杜邦连环替代复算**（三效应加和闭合 + 口径差标注）、
   **破产双模型复算**（Altman/Ohlson，含中期报告年化口径卡口与市值单位卡口）、
   **压力情景三档复算**、**现金时序读数复算**（hist<3 期必须 null，填了判 FAIL）；
   v0.0.15 起再加五项：**杜邦三因子下钻复算**（恒等四项分解闭合/堆积定位/杠杆拆解与
   升档判定）、**扣非双版触发校验**（触发条件命中但未填判 FAIL）、**五年累计归因与分位
   复算**（含期间标签一致性）、**周期证据读数复算**、**四线贴线检测复算**（激励线为
   结构+ratio 复算）；peers 块结构校验（src 非空、比率合理区间）
5. 勾稽异常清单（`references/articulation.md` 的三态输出）写入 data.json 的 `recon` 块，
   与 JSON 一同存档于 `reports/archive/json/`

> **定位说明**：calc.py 是算术与一致性守门员，拦「桥不闭合、比率算错、勾稽不平、
> 无出处数字」；它**不能**验证数字本身是否忠于原文——那仍靠出处链与 Phase 1 双源核对。

### Phase 8：输出报告

1. 复制 `assets/report-template.html` 为最终文件名，按模板内注释逐槽位填充；
   **机械槽位（数字/徽章/语义色/SPARK 数组/TREND/SEG_BRIDGE/OCF_BRIDGE/HOLDERS/
   DUPONT_STACK/peers 表/watchlist 卡）照 `{stem}.fillsheet.md` 速查表抄**
   （--fill 产物，v0.0.18 起全槽位覆盖），判断槽位（figtitle 裁决/takeaway/三问/归因措辞）自己写；
   模型不手写 CSS，只替换内容与数据。
   **数字一律从 fillsheet 复制，禁凭记忆手写**（万华轮 check_html 首轮 11 处笔误的教训）；
   **分两段填充（v0.0.18 笔误前移）：先填 s0~s3 → 立即跑 `check_html.py --json`
   （T8① 数字回验）→ 清零后再填 s4~s8 → 走第 4 条全量门禁**。
   **读法层（v0.0.7 硬规则）**：figtitle 一律
   「结论式」——标题即判断，方法说明/口径注记挪 srcline，不占标题；复杂表
   （≥4 行或含多方向读数）在 srcline 前加一行 `.takeaway` 读法行。
   三层各归其位：标题说结论、表格给证据、srcline 给出处。
   **srcline 只写对外来源**（v0.0.18 禁词门禁）：定期报告/公告/Tushare/东方财富；
   底稿文件名/方法库路径/脚本名/字段路径/版本号一律不进可见文本。
   **归因类图表的四段式（杜邦/因素桥，评审定案）**：归因只是中间步骤——
   figtitle 必须四段完整：**变化方向 → 靠什么（归因）→ 这意味着什么（经营含义）
   → 盯什么（前瞻验证）**。禁止只报归因停在第一层（反例：「ROE +1.06pct：总资产
   周转率独扛（+2.3pct），净利率五年来首次回落」——读者看不出好坏与风险）。
   **缩写纪律（评审定案）**：正文缩写首次出现必须给中文全称 + 一句白话解释
   （例：经营现金流净额（OCF）——公司做生意实际收到的现金；之后可用缩写）；
   数据徽章、图表刻度内缩写豁免。
   **S1~S7 版面规格唯一出处 = 模板注释**（report-template.html 各槽位注释块：四维表五列/
   趋势四宫格 2×2/杜邦双卡/ΔROE 堆叠条分色与五年累计列/桥图尺寸与端点/行序与分组行/
   分位 X/5 措辞/断言表结构/健康检验固定主题序与汇总口径/Q4 卡年报专属）——
   填充时模板就在手上，**照抄槽位、不凭记忆改版式**；机检兜底（s1-v15-shape/dupont-stack/
   s1-grid4/abbrev/ocf-bridge-shape/figtitle 族/inspection-verdict）由 check_html 承载。
   **可见数字精度（v0.0.19 硬纪律）**：报告可见数字一律 ≤2 位小数（pct 效应值 1 位）——
   fillsheet 机械槽位已转好照抄即可，JS 图表标签由 fmt 助手兜底，原始精度留 data.json 底稿。
2. 报告类型差异（哪些模块可裁剪）见 `references/report-types.md`：
   - 年报 = 全模块；半年报 = 同比为主 + 注明未经审计；季报 = 仅 P2/P4/P7 精简版；
     招股书 = 三年一期趋势 + 募投项目 + 发行前后股权 + 风险提示专章（权重上调），
     股东户数/机构预期等二级市场模块裁剪
3. **下期跟踪清单（P2-18）**：按 data.json 的 `meta.industry_profile`，从
   `references/industry-profiles.md` 取该模式的「先行指标建议集」（3~5 项）定制；
   无法归类时用通用缺省集（合同负债剪刀差 + 资本开支节奏 + 按行业补 2 项）并声明理由。
   每条必须写成**条件化触发线（if-then，可证伪）**，同时写入模板仪表盘槽位与 data.json
   的 `watchlist` 块，供下次同公司分析回看。
   **阈值带（T5）**：每条在 if-then 之外优先给出**上下阈值**（至少一侧，四键形态见
   extraction-schema.md watchlist 节）——阈值必须有依据（历史中枢 / 同业水平 / 管理层指引）
   并写进 `source`/`note`；无法数字化阈值的指标允许只保留 if-then 句式。
   **冻结纪律（T6）**：产出后 watchlist 原字段只读不回改，回看只追加 `review` 子块（回看侧动作见 Phase 0 第 5 条）。
4. **报告机检**：`python "<技能目录>/scripts/check_html.py" reports/xxx.html --json reports/archive/json/xxx.json`
   （**或单入口 `scripts/gate.py <html> <json> [--min-recon N] [--png 目录] [--verbose]`**：calc → check_html --json →
   check_render 一条命令串完，统一退出码，省编排防漏跑；明细截断/排障时加 `--verbose`，
   明细全打且 gate 透传——比亚迪轮排障读 278 行源码的教训）。
   校验占位符是否漏填、裸数字（置信度徽章覆盖）、数据来源标注、模板硬规则、必备要素
   （下期跟踪清单/免责声明）、锚点完整性、s8 阈值形态、回看归因。
   **数字回验（T8，`--json` 时启用）**：①级 HTML 数字 ↔ data.json 笔误检测（仅对数值上
   可唯一归因的「独特值」，0.5% 窗口，FAIL 级）；②级 data.json ↔ 原文 md 按 src 行号
   回核（5% 容差 + 元/万/亿/千元单位换算 + 行号窗 ±2，md 缺失跳过并声明）。FAIL 未清零不得交付。
   **门禁暴露技能缺陷时（v0.0.22 用户定案，废 v0.0.14 当场修）**：一律不修技能源——
   可提示用户、可想办法绕过正常出报告、必须记入 handoff 待办；绕过只许在呈现层
   （手工补图/降级声明），禁止为过门禁改数据或 fixture；门禁 FAIL 确系技能 bug 误报时，
   报告备注与 handoff 写明「该 FAIL 为技能 bug 误报、人工确认豁免」才可带病交付。
   理由：多份报告并行共享同一技能源，当场修互相污染（埃斯顿轮 ncrline 修复混入并行
   工作区实证）；技能修订只在专门修订轮做。
5. **渲染门禁（可选但默认执行，v0.0.9 L2，v0.0.11 起双视口）**：`python "<技能目录>/scripts/check_render.py" reports/xxx.html`
   headless Chrome/Edge 真渲染后测量呈现问题（**桌面 1100px + 窄屏 390px 双视口**各一轮）：
   SVG 文本重叠（两轴相交 >1px）、HTML 元素溢出 .sheet（滚动容器内元素豁免）、
   横向裁剪（仅 overflow hidden/clip；auto/scroll 是模板有意滚动设计，不算）、
   **页面级横向溢出**（pageclip：骨架非流式或元素撑破视口，仅对含 .sheet 的报告页）。
   静态正则看不到渲染后状态，图表标签压柱/重叠只能靠它抓。找不到浏览器时打印跳过声明
   + exit 0（不阻塞交付，check_html 硬门禁地位不动）；发现问题 exit 1，修呈现后再交付。
   旧版式存量报告的问题记录在案、不追溯（AGENTS 纪律 7）。
   **视觉验收（v0.0.9 L4，机器优先——评审修订）**：呈现问题以 check_render 机器判据为准
   （含字体回退检测：渲染后实际字体非朱雀仿宋时 WARN）。**人眼截图验收只在两个触发
   条件下执行**：①渲染门禁报出 WARN/问题待定性；②模板或绘图函数改动后的首份报告
   （跑 `check_render.py reports/xxx.html --png <临时目录>/` 按章分片，模型用 ReadMediaFile
   逐章看图；机器判据测不到出界到 SVG 画布外的点/线——万科 ROE 线两点被顶出上缘漏检的
   教训，目检须确认折线全部数据点与标签在画布内）。常规报告机器门禁全绿即交付，不强制
   逐章截图；触发人眼验收时交付语含「已视觉验收」。截图为临时产物，验完即删
6. 对话内回复：报告路径 + 三大亮点 + 三大风险

## 质量门禁（硬性）

1. 三表关键数字必须双源核对（原文 vs tushare），不一致以原文为准并标注
2. **calc.py QC 全绿（exit 0）是写报告的前置条件**——FAIL 未清零不得进入 Phase 8
3. 每条亮点/风险必须附出处（章节/附注/原句）；图表与表格下方标 `数据来源：…`
4. **关键数字必须带置信度徽章（P2-19）**：披露 `.badge.disc` / 推算 `.badge.der` /
   估算 `.badge.est` 三级——报告中不允许出现「裸数字」
5. 金额 ≥1000 带千位符；估算值必须标「估算」
6. 不得输出买卖建议；结尾固定免责声明「本报告仅为信息分析，不构成投资建议」
7. 模板硬规则：浅色卡片风、禁外部字体/CDN/JS、禁暗色背景与渐变投影
8. **报告 HTML 机检（`scripts/check_html.py`）exit 0 是交付的前置条件**——占位符漏填、
   模板硬规则违规、必备要素缺失（下期跟踪清单/免责声明）不得交付；
   裸数字检查为启发式，命中项列「待人工确认」清单逐条判断

## 委派边界

- **可委派（省上下文时）**：md 超长时按章节委托子代理提取结构化数据——提示词给
  **章节锚点关键词**而非行号（行号跨上下文无效）；同业批量取数同样可委派，回传压缩成表
- **禁委派**：最终结论、亮点/风险清单的判定、报告填充——主会话完成
- **单上下文降级**：本会话无法再起子代理（自身已在子代理中）或 md 体量可控时，
  全部主会话执行，用 Grep 锚点 + Read 分页控制上下文消耗
