## 一、这个项目是什么

一个**上市公司年报/半年报/季报/招股说明书分析技能**。用户把报告文件拖进对话，
技能把它转成 markdown、抽取结构化数据、跑勾稽验算与排雷、做因素分析与文字分析，
最后产出一份单文件自包含 HTML 报告。

核心设计：**四层分析引擎**，每层结论都能回溯到下层证据
```
数据层（extraction-schema.md 的 data.json）
  → 恒等式层（articulation.md 的过程勾稽）
    → 比率与基准层（frameworks.md）
      → 叙事层（text-mining.md 的断言验证）
```

### 三道机器门禁 + 一条回归

1. **`scripts/calc.py`（数据层，Phase 7.5，写报告前）**
   校验：结构/出处、核心科目覆盖度、资产=负债+权益、未分配利润滚动、三座桥闭合
   （净利桥/OCF 调节桥/收入三效应）、比率复算（含 dfl/dol/non_main_rev_share/ocf_to_liab）
   与 5 期 hist 逐期复算、勾稽三态一致性（A/B 组 + D 组 manual 型）、分部自洽、
   断言结构、勾稽覆盖率、应付未付利息、信号结构。exit 0 才允许进入 Phase 8。
2. **`scripts/check_html.py`（报告层，Phase 8，交付前）**
   校验：占位符漏填、裸数字（启发式）、数据来源标注、模板硬规则、必备要素
   （下期清单/免责声明）、章节编号、锚点完整性、s2 瘦身形态、s8 阈值形态、回看归因；
   `--json` 启用 **T8 数字回验**：①级 HTML↔data.json 笔误检测（独特值 0.5% 窗口 FAIL）+
   ②级 data.json↔原文 md 行号回核。exit 0 才允许交付。
3. **`python tests/run_regression.py`** —— 任何改动后必跑，**49 条断言**全绿才算没改坏
   （含 calc 双例 + check_html 冒烟 + T8 数字回验 + 构造用例）。

## 三、本轮最有价值的三个发现（交接重点）

### 1. 勾稽引擎能纯靠数字指认造假机制
康得新 2018 样本上，**A6 Capex 勾稽**算出：资本开支 34.99 亿（同比 +945%），
但固定资产+在建工程只净增 5.05 亿，缺口 26.79 亿 —— 直接指向「其他非流动资产」里
预付赛鼎宁波的 21.74 亿设备款（审计报告写明"连一个包装盒也没见到"）。
**这个结论不依赖任何事后公告，纯粹从等式推出。**

### 2. 勾稽闭合 ≠ 科目真实（最重要的认知）
康得新 **A1 现金勾稽算术上是闭合的** —— 因为公司把 122.10 亿已被《现金管理合作协议》
资金归集的存款，自己计为可用现金。**造假者能在自己的账套里把等式做平。**
已写入 `articulation.md` 使用总则第 4 条：勾稽闭合只证明内部自洽，
审计意见/独董异议/问询函/期后违约的信息优先级**不低于任何等式**。

### 3. 三次基于证据的自我纠错（教训）
- **A7 隐含利率误报**：首版只用短借+长借+应付债券（85.31 亿）算出 8.2% 判命中，
  漏了「一年内到期非流动负债」。用完整有息负债两期平均（112.18 亿）重算是 **6.23%，不成立**。
  → 教训：有息负债必须取全科目。
- **港股方案基于不存在的工具**：原计划写用 `westock` CLI 做港股双源，实测该命令不存在；
  tushare 港股财报接口（`hk_income`）返回 40203 无权限，只有 `hk_daily` 行情可用。
  真正能用的是**妙想 `mx_hk_finance_data`**。
  → 教训：外部工具方案必须先实测再写进文档。
- **版本号前提错误**：交接方以为版本是 0.0.1，实际仓库里从未出现 0.0.1。
